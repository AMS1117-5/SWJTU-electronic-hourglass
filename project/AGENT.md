# 1. 项目目标

本项目是一款用于招新礼物的掌上“电子沙漏”。

硬件由以下主要部分组成：

* STM32F030C8T6 主控；
* MPU6050 六轴传感器；
* 两块 8×8 LED 点阵；
* 两颗 MAX7219 LED 驱动芯片；
* K1、K2 两个用户按键；
* 蜂鸣器；
* 锂电池及充电、电源管理部分。

软件提供四个菜单项目：

1. **沙漏**
2. **电子海洋**
3. **时间设置**
4. **亮度设置**

设备上电后默认进入“沙漏”功能。

| MAX7219 CS  | PA4       |      14 | 显示片选 / LOAD           |
| MAX7219 CLK | PA5       |      15 | SPI1_SCK              |
| MAX7219 DIN | PA7       |      17 | SPI1_MOSI             |
| 蜂鸣器         | PB0       |      18 | TIM3_CH3 PWM          |

## 2.1 MPU6050

接口：

* I2C1
* SCL = PB6
* SDA = PB7
* AD0 = GND

因此 MPU6050 的默认 7-bit I2C 地址：

`0x68`

软件中不得默认使用 `0x69`。

推荐初始化：

* Accelerometer：±2 g
* Gyroscope：±250 °/s
* Sample rate：100 Hz 左右
* I2C：100 kHz 或 400 kHz

本项目最重要的是重力方向，而不是高精度姿态解算。

# 4. MAX7219 软件接口

优先使用：

`SPI1`

建议：

* PA5 = SPI1_SCK
* PA7 = SPI1_MOSI
* PA4 = 普通 GPIO，手动控制 CS

不需要 MISO。

建立如下抽象：

```c
void Display_Init(void);
void Display_Clear(void);
void Display_Update(void);

void Display_SetPixel(int x, int y, bool state);
bool Display_GetPixel(int x, int y);

void Display_DrawBitmap(...);
```

上层程序禁止直接操作 MAX7219 寄存器。

# 5. 虚拟显示坐标系

软件统一把两块 LED 点阵抽象成：

`16 × 8 framebuffer`

坐标：

```text
x = 0 ... 15
y = 0 ... 7
```

上层沙漏、海洋、菜单、数字显示全部只操作这个 framebuffer。

例如：

```c
uint16_t framebuffer[8];
```

或者：

```c
uint8_t framebuffer[8][2];
```

均可。

## 5.1 实机标定结果与映射

实机标定的观察基准（用户确认）：充电接口朝下接触桌面，板子竖立，LED 面朝观察者，称为“正向”。
实物两块点阵称为“上面一块 / 下面一块”，不以软件中的 left/right 命名实物。
反馈单点位置时，每块点阵独立按第 1～8 行（从上到下）、第 1～8 列（从观察者左到右）计数。
软件仍使用上述从 0 开始的 16×8 虚拟坐标；两者对应关系通过单点标定确定。

两轮实测记录见 `project/CALIBRATION.md`。设备 0 对应上面点阵，设备 1 对应下面点阵；
根据实测采用的行段位表为 `{6,5,4,3,2,1,0,7}`，列 digit 索引表为 `{7,6,5,4,3,2,1,0}`，
通过 `display.c` 的查表完成接线转换。用户已确认修正后的显示测试全部正确，点阵方向标定完成。
在此正向姿态下，修正后虚拟 x=0..7 表示上面第 1～8 行，x=8..15 表示下面第 1～8 行；
虚拟 y=0..7 表示从观察者左到右第 1～8 列。故虚拟 +X 对应实物向下、+Y 对应实物向右。
本文其余“屏幕右/下”是虚拟 16×8 图中的方向，不应混同于上述实物竖立姿态。
后续 Motion 输出应与修正后的虚拟显示坐标一致，传感器轴映射实测记录与当前实现见第 6 节。

以下内容不能仅依赖原理图确定：

* 两块点阵实际在 PCB 上的左右顺序；
* 每块点阵是否上下颠倒；
* 是否需要 X/Y 镜像；
* MAX7219 digit/segment 与实际 LED 坐标的对应关系。

因此底层必须提供坐标转换层，例如：

```c
#define MATRIX0_FLIP_X
#define MATRIX0_FLIP_Y
#define MATRIX0_ROTATE

#define MATRIX1_FLIP_X
#define MATRIX1_FLIP_Y
#define MATRIX1_ROTATE
```

或者使用映射表。

**上层算法不得包含针对 PCB 接线方向的特殊处理。**

# 6. MPU6050 坐标系统

用户已反馈三种静止姿态，详见 `project/MPU6050_CALIBRATION.md`：

* 充电口朝下竖立：AX≈−1 g、AY≈0、AZ 为负且约一格；
* LED 面朝观察者，充电口转向左侧：AY≈+1 g，其余轴接近零；
* LED 面朝上平放：AZ≈−1 g，其余轴接近零。

配合第 5 节修正后的虚拟坐标，当前采用 `gravity.x = -AX / |A3D|`、
`gravity.y = +AY / |A3D|`，在 motion 层滤波后做三维归一化再取二维投影。
这里的轴符号来自实测；用户已确认重力光点在正向、倒置、左右旋转和平放时方向全部正确。
不得直接把某姿态下的非主轴小读数当作零偏扣除。

因此建立统一的软件重力坐标：

```c
typedef struct
{
    float x;
    float y;
} Gravity2D;
```

其中：

```text
x > 0 ：屏幕右方
x < 0 ：屏幕左方

y > 0 ：屏幕下方
y < 0 ：屏幕上方
```

MPU6050 驱动只负责输出传感器原始数据。

另外建立：

```c
Gravity2D Motion_GetDisplayGravity(void);
```

由该函数负责：

```text
MPU6050 坐标
        ↓
PCB 坐标转换
        ↓
LED 屏幕坐标
```

以后沙漏和电子海洋禁止直接访问 MPU6050 原始 XYZ。

# 7. MPU6050 姿态算法

本项目没有必要实现完整 AHRS。

不需要：

* Kalman Filter；
* 四元数；
* DMP；
* 绝对航向；
* 磁力计。

核心需求只是：

**得到相对于屏幕的重力方向。**

建议读取：

```text
AX
AY
AZ
GX
GY
GZ
```

然后主要使用 accelerometer。

进行简单低通：

```text
filtered = filtered × 0.80
         + measured × 0.20
```

注：用户实机反馈希望响应稍快，已将新样本权重从 15% 调为 20%，
集中配置在 `Config/app_config.h` 的 `MOTION_FILTER_NEW_PERCENT`。

再根据实机确定的轴映射产生：

```c
gravity.x
gravity.y
```

归一化后作为粒子系统的重力方向。

电子海洋模式可以适当降低滤波强度，使快速摇动设备时沙子/水滴具有更明显反应。

# 12. 沙漏模式

这是默认功能。

## 12.1 基本视觉结构

整个 16×8 framebuffer 显示一个电子沙漏。

沙漏具有：

* 上腔；
* 中央狭窄通道；
* 下腔；
* 若干代表沙子的亮点。

不要把沙漏做成单纯的倒计时数字。

沙子的空间位置必须随着设备姿态发生变化。

---

# 13. 沙漏的核心物理规则

沙漏不是简单：

```text
remaining_time--
```

而应模拟：

```text
重力
↓
沙粒移动
↓
沙子通过瓶颈
↓
一侧减少
↓
另一侧增加
```

因此：

**“剩余时间”的本质是剩余沙量，而不是一个独立的计时器。**

---

# 14. 沙漏时间定义

默认：

```text
默认单粒间隔 = 10 秒（同时也是设置上限）
整轮时间 = 可见粒子数 × 单粒间隔
当前 24 颗 × 10 秒 = 240 秒 = 4 分钟
```

这里的整轮时间定义为：

> 设备标准竖直摆放、重力方向与沙漏中心轴平行时，一侧全部沙子完全流向另一侧所需的时间。

今后调节时间时只能缩短单粒间隔，不能调到大于 10 秒；如界面显示整轮时间，
其上限必须由 `粒子数 × 10 秒` 推导。不要把“整轮 10 秒”和“每颗 10 秒”混淆。

如果设备倾斜：

流速降低。

如果接近水平：

沙子停止或几乎停止穿过瓶颈。

如果设备倒置：

流动方向反转。

# 15. 沙漏流速模型

定义沙漏主轴单位向量：

```c
hourglass_axis
```

定义当前屏幕重力方向：

```c
gravity
```

计算：

```c
axisGravity = dot(gravity, hourglass_axis);
```

则：

```text
axisGravity > 0
A → B

axisGravity < 0
B → A
```

流量大小建议：

```c
speedFactor = abs(axisGravity);
```

增加死区：

```text
speedFactor < 0.15
→ 不允许通过瓶颈
```

标准竖直：

```text
speedFactor ≈ 1
```

---

# 16. 定时精度与粒子动画必须分离

不可让整个沙漏时间直接由 LED 粒子的移动速度决定。

原因：

屏幕只有 128 个像素。

如果只有约 20~40 个沙粒，却需要流数分钟，则直接靠粒子跨越瓶颈会非常不稳定。

因此：

## 物理量 1：沙量

使用高精度内部数值，例如：

```c
float sand_amount_A;
float sand_amount_B;
```

或定点数。

满足：

```text
A + B = 1.0
```

竖直情况下：

```text
flowRate = 1 / hourglass_duration
```

实际：

```text
flowRate =
    speedFactor
    / hourglass_duration
```

根据重力方向：

```text
A → B
```

或：

```text
B → A
```

## 物理量 2：LED 沙粒

LED 粒子只是：

**沙量的可视化。**

因此允许内部沙量连续变化，而显示的粒子数离散变化。

---

# 17. 推荐沙粒模拟方法

不需要 Navier-Stokes 等真正流体计算。

对 16×8 LED 屏幕，推荐：

**Cellular Automata / Particle Simulation**

每一个亮点代表一个沙粒。

建议：

```c
#define MAX_PARTICLES 32
```

单个粒子：

```c
typedef struct
{
    int8_t x;
    int8_t y;

    float vx;
    float vy;
} Particle;
```

也可以完全使用整数网格。

每次更新：

1. 根据 gravity 判断主要运动方向；
2. 尝试向重力方向移动；
3. 如果被其他沙粒阻挡：

   * 尝试左下；
   * 尝试右下；
4. 如果仍被阻挡：

   * 保持位置；
5. 根据少量随机数避免形成完全固定结构。

---

# 18. 瓶颈控制

沙漏中必须存在固定墙体 mask：

```c
hourglass_wall_mask[8]
```

粒子：

* 可以在沙漏腔室内部移动；
* 不得穿过墙；
* 只能从中心 neck 穿过上下两腔。

但是：

粒子是否允许穿过 neck，必须受到：

```text
hourglass_duration
```

控制。

也就是说：

**粒子运动可以快，但穿过瓶颈必须慢。**

这样既能保持良好的动画，又能确保：

```text
24 颗、每颗 10 秒设置 ≈ 4 min 流完（标准竖直）
```

---

# 19. 沙漏启动行为

设备进入沙漏模式时：

先等待 MPU6050 数据稳定，例如：

```text
300~500 ms
```

检测当前重力方向。

将全部沙子初始化到：

**当前位于上方的沙漏腔室。**

这样无论用户拿着设备哪一头朝上：

进入沙漏后都可以直接开始流动。

---

# 20. 沙漏翻转

当全部沙子进入一个腔室：

```text
TRANSFER_COMPLETE
```

触发完成事件。

如果用户随后将设备翻转：

此前装满沙子的腔室自然成为上腔。

沙子重新向另一边流动。

不需要按 Reset。

因此这个电子沙漏应像真实沙漏一样：

```text
流完
↓
翻过来
↓
自动开始下一轮
```

# 21. 完成提示

当检测到：

```text
任意一仓的可见沙粒数量从非零变为零（最后一颗沙粒跨过瓶颈）
```

调用：

```c
Alarm_Start();
```

蜂鸣器演奏一段约：

**5 秒**

的旋律。

旋律结束后：

* 沙漏画面继续显示；
* 不进入菜单；
* 不自动重置沙子。

再次翻转即可开始下一轮。

使用非空→空仓的边沿检测和一次性待处理事件，避免同一空仓状态每帧重触发。
上电初始化时本来就空的那仓不触发。中途翻转、沙子全部流回原仓也要触发，
不得限定“本轮起始仓”或再等待额外的完整计时周期；正放反放都按实际过砂结果判断。
时间设置控制过砂流速，完成提示本身仅以可见沙仓清空事件为准。

# 22. 蜂鸣器

MCU：

```text
PB0
```

使用：

```text
TIM3_CH3 PWM
```

不要仅使用 GPIO 高低电平。

原因：

需要改变频率以演奏旋律。

建议提供：

```c
void Buzzer_Init(void);
void Buzzer_PlayTone(uint16_t freq, uint16_t duration);
void Buzzer_Stop(void);
void Buzzer_Update(uint32_t now);
```

旋律必须：

**非阻塞播放。**

禁止：

```c
HAL_Delay(5000);
```

整个 5 秒旋律期间：

* LED 动画继续刷新；
* MPU6050 继续采样；
* 按键继续响应。

# 24. 电子海洋物理规则

粒子受到当前 gravity 影响。

设备向左倾：

粒子向左堆积。

设备向右倾：

粒子向右堆积。

设备倒转：

粒子向新的“下方”移动。

用户快速摇动设备：

加速度变化应使粒子出现明显扰动。

电子海洋：

* 没有计时；
* 没有 neck；
* 没有蜂鸣器完成事件；
* 没有上下两个独立沙仓。

粒子不能离开 16×8 屏幕边界。

# 25. 设置模式

时间设置以**标准竖直时的单粒间隔**为约束，整轮时间由粒子数乘以该间隔推导。

* 界面按整轮时长调节：30～240 秒，步进 30 秒。
* 24 颗沙粒对应单粒间隔最小 1250 ms，最大 10000 ms，每档间隔差 1250 ms。
* 默认 10000 ms；以后允许调小，不允许调大到超过 10000 ms。
* 当前 24 颗粒子的整轮默认值/上限均为 240 秒。
* 单粒间隔无需为整数秒；例如整轮 30 秒对应每颗 1.25 秒，90 秒对应每颗 3.75 秒。
* 内部采用毫秒，避免缩短到非整数秒时丢失精度。
* 原定 1～15 分钟范围仍取消；30 秒步进按用户最新反馈采用。

# 27. 设置操作

设置界面：

### K1 短按

整轮时间增加 30 秒，但在单粒间隔达到 10 秒时停止增加，不得超过上限。
整轮时间的当前上限对应 4:00；若粒子数量变化，必须重新推导上限。

### K2 短按

整轮时间减少 30 秒，最小 30 秒（每颗 1.25 秒），到达下限后停止，不循环、不变成零或负数。

### K1 长按

保存当前设置并退出设置。

返回：

```text
APP_MENU
```

修改沙漏时间不清空当前沙子状态。

新的 duration 立即用于后续流速计算。

V1.0 暂不要求写入 Flash。

因此重新上电后：

```text
恢复默认每颗 10 秒，当前 24 颗对应 4:00
```

如果以后需要掉电保存，再增加 Flash Settings 模块。

## 27.1 亮度设置

主菜单第 4 项。上屏显示太阳图标，下屏显示数值 0、1、2。
K1 短按增加一档，K2 短按减少一档，到达边界后停止，不循环。
更改立即通过 Display 层应用到两颗 MAX7219，不清空 framebuffer。
K1 长按保留当前 RAM 设置并返回菜单；重新上电恢复默认 0 档。
0 档是 MAX7219 最低亮度，不是关屏。K2 长按仍无功能。

# 36. 最终设计原则

本项目的核心体验不是“一个会倒计时的 LED 屏”。

而应该是：

> 一个真的具有方向、重力和沙量概念的电子沙漏。

因此软件设计应始终保持以下关系：

```text
MPU6050
   ↓
Gravity2D
   ↓
Particle Physics
   ↓
Hourglass / Ocean
   ↓
16×8 Framebuffer
   ↓
MAX7219
   ↓
LED Matrix
```

不同模块之间不得跨层访问。

尤其禁止：

```text
Hourglass 直接读取 MPU6050
Hourglass 直接操作 MAX7219
Ocean 直接操作 GPIO
Menu 直接发送 SPI
```

所有硬件细节必须留在驱动层。

这样后续即使：

* LED 点阵方向改变；
* MPU6050 方向改变；
* 粒子算法升级；
* 更换显示驱动；

上层应用逻辑都不需要重写。
