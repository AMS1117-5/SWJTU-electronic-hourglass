# MPU6050 通信与轴方向标定

本文页面操作对应 **Diagnostic 固件**，正式版操作见 `README.md`。

点阵映射、三种静止姿态与重力光点方向均已由用户实机确认，方向标定完成。
暂不做陀螺仪零偏或六面比例校准。

## 地址和初始化

- AD0 接地：7 位地址为 `0x68`。
- STM32 HAL 地址参数为 `0x68 << 1`，即 `0xD0`；HAL 自动处理读写位。
- WHO_AM_I 位于寄存器 `0x75`，MPU6050 预期读回 `0x68`。它是身份寄存器，不是总线地址扫描结果。
- I2C1：PB6/SCL、PB7/SDA，保留 CubeMX 现有 timing。
- 上电等待、复位等待、唤醒等待均通过 tick 状态机完成，没有 HAL_Delay。
- 加速度 ±2 g（16384 LSB/g），角速度 ±250 °/s（131 LSB/(°/s)）。
- DLPF=3，1 kHz 基准 / 10 = 100 Hz；启用 DATA_RDY 并轮询状态，不需要 MPU6050 的 INT 引脚。
- 一次读出 INT_STATUS 和紧随其后的 14 字节六轴/温度快照，只有 DATA_RDY 有效才发布新样本。
- I2C 使用短时限同步事务，参数超时 5 ms；STM32F0 HAL 内部另有 BUSY 等待上限约 25 ms。
  故障后停止发布数据，约每 500 ms 重新尝试初始化，不在每次主循环中连续重试。

## 页面和按键

Diagnostic 固件上电默认进入沙漏，长按 K1 进入海洋，松开后再次长按 K1 进入重力光点/三轴观察组。
重力光点页在传感器初始化完成后收集约 400 ms 新样本，随后显示单个光点。
光点位于屏幕中央加上重力投影偏移的位置；它指示重力方向，不是带惯性的粒子。
平放时应靠近两块屏交界的中央，竖立时应靠近实际较低的一侧。
400 ms 等待期或加速度模长过小时显示 `G` 和横线。

K2 短按切换到原始三轴观察页，显示方式如下：

- 上面点阵：`X` / `Y` / `Z` 表示当前查看 AX / AY / AZ。
- 上面右下角小点：随成功采样的时间闪动，作为数据更新提示。
- 下面点阵：`+` 表示正，`−` 表示负，单点表示接近零（绝对值小于约 0.0625 g）。
- 下面最底部两行：幅值条，长度 0～8 格对应约 0～1 g；超过 1 g 以满格显示。
- K2（PA0）短按：重力光点 → X → Y → Z → 重力光点。
- K1（PA1）短按：反向选择。
- K2 长按：不操作。
- K1 长按：沙漏 → 海洋 → 传感器测试 → LED 四角标定 → 原 LED/按键诊断 → 沙漏。
  每次长按只切换一次，需要松开后再按。

启动期间上下各一条横线。故障时上面显示 `E`、下面显示编号：

| 编号 | 含义 |
|---|---|
| 1 | I2C 事务失败：未应答、总线忙或传输超时 |
| 2 | WHO_AM_I 不为 0x68 |
| 3 | 连续约 100 ms 没有新数据，或样本过期 |

原始三轴观察页只对显示用的原始加速度做轻度低通，驱动输出始终是未经方向变换的六轴原始值。
重力光点则只读取 Motion 输出，Motion 的轴映射参数见 `Config/app_config.h`。
可通过调试器查看 `Mpu6050_GetWhoAmI()` 和 `Mpu6050_GetSample()`；当前界面不显示角速度。

## 实机记录

保持设备静止约 1 秒再记录；每种姿态分别切换查看 X、Y、Z，记录符号和幅值条长度即可。
标定时不摇动设备，动态加速度会影响读数。

1. **A 正向竖立**：充电口朝下，LED 面朝你。
2. **B 在屏幕平面内旋转 90°**：LED 仍朝你，把充电口转到你看到的左侧。
3. **C 平放**：LED 面朝天花板，背面朝桌面。

| 姿态 | X：符号 / 条长 | Y：符号 / 条长 | Z：符号 / 条长 |
|---|---|---|---|
| A 充电口向下 | − / 8 | 点（接近零） | − / 1 |
| B 充电口向左 | 点（接近零） | + / 8 | 点（接近零） |
| C LED 面朝上 | 点（接近零） | 点（接近零） | − / 8 |

上表是用户实测结果，条长每格约 0.125 g。A 中 Z 的一格保留为实测现象，
可能与轻微倾斜或传感器偏置有关，不能凭单一姿态直接扣除为零偏。

加速度计静止读数是支撑力对应的比力，与物体自由下落方向有符号关系；
Motion 根据以上姿态确定交换/正负方向，再用重力光点验证，不能直接把原始正方向当作沙粒下落方向。

## 当前重力映射

在已标定的虚拟画布中，+x 沿板子指向充电接口，+y 在正向姿态中指向观察者右侧：

```text
gravity.x = -filtered_AX / 三维加速度模长
gravity.y = +filtered_AY / 三维加速度模长
```

B 姿态下板子的原右边朝地面，AY 为正，所以虚拟 +Y 的符号为正。
低通按每个新样本更新一次：旧值 ×0.80 + 新值 ×0.20。
根据用户实机反馈，将新样本权重从 15% 小幅提高到 20% 以改善响应，
可通过 `Config/app_config.h` 的 `MOTION_FILTER_NEW_PERCENT` 调整。
模长使用 AX/AY/AZ 三个分量计算，再投影到二维；不能把 AX/AY 的二维投影重新归一化，
否则平放时微小噪声也会被放大成满量程重力。
传感器数据失效时 Motion 输出零并标记无效；恢复后重新等待稳定样本。

## 光点验证

1. 充电口朝下：光点在下面点阵靠近底部。
2. 充电口朝上：光点转到原上面点阵靠近顶端，即当前实际最低的一端。
3. 充电口向左：光点偏向板子原右边（此时朝地面）。
4. 充电口向右：光点偏向板子原左边（此时朝地面）。
5. LED 朝上平放：光点靠近两块屏交界中央，不应被微小噪声推到边缘。

屏幕是偶数行列，中心落在四颗 LED 之间；显示到相邻的某一颗都属于中央位置。
用户已确认上述方向全部正确，现在进入共享粒子系统/电子海洋阶段。

## 构建

在此目录下从 WSL 执行：

```bash
/mnt/c/msys64/ucrt64/bin/cmake.exe --preset Diagnostic
/mnt/c/msys64/ucrt64/bin/cmake.exe --build --preset Diagnostic
```

烧录 `build/Diagnostic/project.elf`。正式菜单与设置使用 `build/Release/` 中的固件。
