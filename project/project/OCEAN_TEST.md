# 电子海洋：实机测试

本文操作对应 **Diagnostic 固件**。正式 Release / Debug 通过主菜单选择海洋，操作见 `README.md`。

显示映射、MPU6050 轴映射和重力光点方向已由用户确认。本阶段验证共享粒子系统。

## 使用

烧录 `build/Diagnostic/project.elf`。上电默认进入沙漏，长按 K1 进入电子海洋，先看到散布的 32 个点，
传感器初始化并稳定后开始运动。整个 16×8 画布是连续容器，两块点阵之间没有墙或瓶颈。

- K2（PA0）短按：重新散布 32 个点，方便重复观察下落过程。
- K1（PA1）长按约 700 ms：切换诊断组，依次为
  **沙漏 → 海洋 → 重力光点/三轴观察 → LED 四角标定 → 原 LED/按键诊断 → 沙漏**。
- 每次长按只切换一次，需要松开后再长按。
- 海洋中的 K1 短按和 K2 长按不操作。
- 离开海洋时暂停粒子，返回时继续原状态，不补算离开期间的模拟时间。
- 传感器数据无效时粒子保持原位。若一直不动，可长按 K1 查看传感器页的错误码。

这是独立诊断操作；正式菜单和设置已经在 Release / Debug 版本接入。

## 观察顺序

保持之前的方向基准：充电口朝下接触桌面，LED 面朝你，实物分为上/下点阵。

1. **正向竖立**：散点应落到下面点阵底部，并逐渐摊开。
2. **缓慢向两侧倾斜**：点应向实际较低的一侧重新堆积。
3. **倒置**：原来的上面点阵现在朝下，粒子应穿过两屏交界并落向该端。
4. **反复翻转**：仍然保持 32 个点，不应叠成更少的点或跑出屏幕。
5. **LED 面朝上平放并静止**：平面重力接近零，点应基本停住。
6. **短促摇动后停下**：粒子应有明显扰动，随后在重力下重新堆积。
7. **进入诊断再返回海洋**：验证按键仍响应，画面继续而非重置。

反馈重点：下落方向、连续性、响应速度、摇动效果，以及是否有卡点/漏点/明显卡顿。
实机观感确认后，再进入沙漏几何和瓶颈流量阶段。

## 实现参数

- `Config/app_config.h`：`OCEAN_PARTICLE_COUNT=32`，`PHYSICS_PERIOD_MS=20`。
- 重力低通新样本权重 `MOTION_FILTER_NEW_PERCENT=20`（原 15），响应稍快。
- MAX7219 亮度 `DISPLAY_INTENSITY=0`（原 2），为 0～15 档中的最低亮度，仍正常显示。
- `Physics/particles.c`：静态粒子数组与占用位图，无动态内存。
- 粒子每步最多移动一个相邻网格；打乱更新顺序以避免固定扫描方向偏差。
- 重力大小决定运动额度，倾斜决定直行/斜向移动比例，小于约 0.08 g 的轴分量忽略。
- 重力方向受阻时尝试下斜方向，轴向重力下偶尔同层扩散，以帮助液面摊开。
- `Motion_GetShakeStrength()`：加速度与低通值的差异转为 0～255 扰动强度；
  小于约 0.25 g 的三轴绝对差总和忽略，静止后逐步衰减。
- 摇动会短暂允许向其他相邻方向移动，但仍遵守占用、墙体和边界检查。
- 粒子引擎支持墙体 mask 供后续沙漏复用；海洋本身没有内部墙。

## 构建

在固件目录从 WSL 执行：

```bash
/mnt/c/msys64/ucrt64/bin/cmake.exe --preset Diagnostic
/mnt/c/msys64/ucrt64/bin/cmake.exe --build --preset Diagnostic
```
